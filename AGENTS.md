# Repository instructions

- Keep every experiment’s `index.html` focused on the animated model, live outputs, essential controls, a relationship graph and its formula. Use the compact optical-bench and Boyle’s-law references as the layout standard.
- Add a compact experiment title and one short description above the workspace on normal pages. Hide both in fullscreen. Do not add hero sections, lesson navigation, quizzes, notebooks, long explanations, promotional content or decorative sections.
- Make the desktop overview fit at 100% browser zoom on a 1366×768 laptop screen. Use compact spacing and readable labels rather than CSS zoom or scaling all text down. Keep models fully inside their stage, place related controls side by side when useful, and retain larger fullscreen framing. Optional `data-overview-viewbox` on the model SVG trims overview whitespace; include every allowed mechanism pose when determining its bounds.
- Put the formula card above the live output cards in the sidebar.
- Put sliders below the model. Use one primary experiment action, Auto explore/Pause and Reset; keep controls functional, keyboard accessible and responsive.
- Put a button labeled **Full Screen** at the model’s top right. Fullscreen shows only the model and live output, plus the exit button. Hide controls, graphs, formulas, badges and surrounding content. Preserve model dragging and keyboard operation. Support Escape, restore focus on exit and provide a fallback when native fullscreen is unavailable.
- Every concept must show movement indicators in fullscreen only. Anchor each label to the actual movable component and update its position during motion and resize. Dragging the label or component must change the same model value; focus the label and use arrow keys, Home and End as well. Label only parts that really move; fixed components get no movement indicator. Use the shared `.move-hint` styles and `positionMoveHint()` helper where appropriate.
- Convex-lens fullscreen also includes the live white-screen preview and labels attached to the movable object and screen. Both components must support independent dragging and arrow-key movement; the lens stays fixed. Return the same preview to the sidebar on exit.
- Preserve the real animated SVG apparatus and correct physics. Respect reduced motion and pause animation when the document is hidden.
- Prefer plain HTML, CSS and JavaScript. Keep shared behavior in the root shared files and experiment-specific behavior in its folder. No build or runtime dependencies are needed.
- Maintain the root and experiment README files. Ignore screenshots, local environments, dependency folders, caches and OS metadata. Commit only necessary source, documentation and runnable checks.
- Run `node check.mjs` after changes to interactions, physics or layout. Review the desktop, phone and fullscreen screenshots in `artifacts/`.

## New physics concepts created with $anatomy

Treat `secondary/boyle/`, `secondary/convex/` and `secondary/ohm/` as the established product standard. Apply these rules automatically when asked to create another physics concept in this repository; do not deliver the skill’s default standalone lesson layout.

1. Read the installed `$anatomy` skill and the closest existing experiment before designing. Follow its physical apparatus, purposeful detail, geometry, depth order, motion and verification guidance. Keep the existing light palette, card styling and compact page structure. These repository requirements take precedence over the skill’s default framing or extra lesson content.
2. Create a clearly named concept folder inside its series folder, containing `index.html`, `app.js`, `style.css` and `README.md`. Reuse the root shared files. For a concept nested one level below the repository root, load `../../shared.css` before the concept stylesheet, and load scripts as `../../geometry.js`, `app.js`, then `../../shared.js`. The page must open directly from disk and work offline, without installation or a build step.
3. Use one compact concept title and one sentence explaining what the student will learn. Below it, use a desktop workspace with the animated SVG apparatus and controls on the left. On the right put the formula first, then live output cards, a relevant physical output preview if needed, and the relationship graph. Stack the workspace on phones. Do not add heroes, navigation, quizzes, notebooks, long explanations or decorative sections.
4. Drive all motion, readouts, preview states and graph points from one physics model. Define units, valid ranges, limits, constants and boundary cases. Document illustrative approximations in the concept README. Provide real dragging, keyboard controls, labelled sliders, a suitable primary action, Auto explore/Pause and Reset. Reset must restore the initial model and graph state. Respect reduced motion and pause work while hidden or offscreen.
5. Use the shared fullscreen behavior with `.stage-wrap` as the fullscreen target, `#stage` as the model region, `#fullscreen` as the top-right button, and `[data-readout]` for current values. Fullscreen contains the apparatus, live output and anchored movement indicators, without sliders, graphs, formulas, page titles or descriptions. Include a compact live physical output preview when it explains the experiment, following the convex white-screen example. Move the same preview DOM node into fullscreen on `model-fullscreen-change` and restore its original place on exit; never duplicate IDs or maintain a separate stale preview.
6. Movement indicators must identify every genuinely adjustable component, support pointer and keyboard input, follow the model’s projection, stay within the phone viewport and disappear outside fullscreen. For multiple adjustable parts, make selection and independent movement clear. Keep all shown values synchronized with the real controls and physics model.
7. Extend `check.mjs` with the new concept’s own physics and interaction cases; do not reuse another concept’s equations or limits. Check the initial state, useful extremes, primary action, reset, dragging, keyboard, auto mode, reduced motion, normal-page hidden indicators, native/fallback fullscreen visible indicators, output synchronization, Escape, focus restoration and preview restoration when relevant. Check desktop, 1366×768 and 1440×900 at 100% zoom, 390 px phone and narrow 320 px layouts. The desktop overview must fit without scrolling or the SVG overlapping controls. Run the Anatomy geometry/line audits when authoring new geometry, and inspect browser screenshots including close-ups of the mechanism.
8. Add the concept to the root README table and document its controls, formula, assumptions and ranges in its own README. Keep the final page source and any necessary portable generation source; do not commit local toolkit installations, absolute-path build dependencies, duplicate generated pages, screenshots, caches, logs or dependency folders.
